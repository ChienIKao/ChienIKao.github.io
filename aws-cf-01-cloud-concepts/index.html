Cloud Concepts Overview — 雲端運算簡介、六大優勢、AWS 概觀、雲端採用框架 (CAF)。針對 AWS Certified Cloud Practitioner 考試整理重點與常見誤區。

# 1.1 雲端運算簡介

生活比喻

以前要用電，你得自己買一台發電機、自己加油、自己維修 —— 這就是自建機房 (on-premises)。現在你只要插插頭，用多少度電付多少錢，發電廠的事完全不用管 —— 這就是雲端運算。

定義

雲端運算 (Cloud Computing): 透過網際網路按需 (on-demand) 取得 IT 資源，並採按使用量付費 (pay-as-you-go) 的模式。你不需要事先購買、擁有、維護實體伺服器與資料中心。

# 三種服務模型

模型你管什麼AWS 範例生活比喻
IaaS (基礎設施即服務)作業系統、應用程式、資料全都自己管EC2租一塊空地，房子自己蓋
PaaS (平台即服務)只管應用程式與資料Elastic Beanstalk 、 RDS租一間裝潢好的店面，直接開門做生意
SaaS (軟體即服務)什麼都不用管，直接用Gmail、Dropbox、 Amazon WorkSpaces直接去餐廳吃飯

# 三種部署模型

模型說明
雲端 (Cloud)應用程式完全建置在雲上，又稱 all-in cloud
混合 (Hybrid)雲端資源與自建機房互相連接、共同運作
自建 (On-premises)全部在自己的資料中心，使用虛擬化技術管理，又稱私有雲

考試重點

IaaS / PaaS / SaaS 的區辨必考。判斷方式: 你要不要管作業系統？要 → IaaS; 你只上傳程式碼，不碰作業系統 → PaaS; 連程式碼都不用寫，開帳號就能用 → SaaS。EC2 是 IaaS 的標準答案，Elastic Beanstalk 是 PaaS 的標準答案。

# 1.2 雲端運算的六大優勢

這六點是 AWS 官方定義， 知識檢查與證照考試都會直接考，建議整組背下來:

#優勢白話解釋
1以可變費用取代前期資本費用不用先砸大錢買伺服器，改成用多少付多少
2享受大規模的經濟效益AWS 客戶多、採購量大，成本攤下來比你自己買便宜
3不必再猜測容量不用賭「要買幾台機器」, 需求變了隨時調整
4提高速度和敏捷性開一台伺服器從數週縮短到數分鐘
5不必再為運行資料中心投入資金省下機房、電力、冷卻、維運人力的錢
6幾分鐘內實現全球化部署想在其他國家上線，選個區域就好，不用飛過去蓋機房

記憶技巧

可以濃縮成三組概念: 省錢 (1、2、5)、彈性 (3)、速度 (4、6)。考題常用改寫過的敘述問你「這描述的是哪一項優勢」, 只要抓住「資本支出變營運支出」「停止猜測容量」「幾分鐘內全球部署」這幾個關鍵句就不會錯。

# 1.3 Amazon Web Services 簡介

AWS 提供上百種服務，課程把它們分成幾大類別。這裡先建立地圖，細節在後面各單元展開:

服務類別代表服務在哪個單元詳談
運算 ComputeEC2、Lambda、Elastic BeanstalkModule 6
儲存 StorageS3、EBS、EFS、GlacierModule 7
資料庫 DatabaseRDS、DynamoDB、Redshift、AuroraModule 8
網路與內容分發VPC、Route 53、CloudFront、ELBModule 5、10
安全、身分與合規IAM、KMS、Shield、WAF、ArtifactModule 4
管理與監管CloudWatch、CloudTrail、Config、Trusted AdvisorModule 9、10
成本管理Cost Explorer、Budgets、OrganizationsModule 2

選擇服務時要考量的因素包括：功能需求、成本、可用性、效能、以及你希望自己管理多少 (對應 IaaS / PaaS / SaaS 的取捨)。

# 1.4 AWS 雲端採用框架 (AWS CAF)

生活比喻

公司搬家不只是「把桌椅搬過去」—— 還要考慮預算怎麼編、員工需要什麼訓練、新辦公室的門禁怎麼設、資訊系統怎麼接。AWS CAF 就是這份搬家檢查清單，提醒你上雲時六個面向都要顧到，不能只想著技術。

定義

AWS Cloud Adoption Framework(CAF): 一套幫助組織規劃雲端遷移的指導框架，由六個觀點 (Perspectives) 組成，分為「業務能力」與「技術能力」兩大類。

分類觀點關注什麼誰負責
業務能力業務 Business確保 IT 投資能對應到業務成果經理人、財務、策略主管
業務能力人員 People人力資源、訓練、組織變革管理人資、人才管理
業務能力治理 Governance專案管理、投資組合管理、風險控管CIO、專案經理
技術能力平台 Platform架構設計、系統與應用程式的實作解決方案架構師、工程師
技術能力安全 Security身分存取管理、資料保護、合規稽核資安長、資安團隊
技術能力營運 Operations日常維運、監控、事件與變更管理IT 維運團隊

考試重點

六個觀點分成三個「業務面」(業務、人員、治理) 與三個「技術面」(平台、安全、營運)—— 考題常問某個觀點屬於哪一類，或某個角色對應哪個觀點。記憶口訣: 業務、人員、治理是「人跟錢」; 平台、安全、營運是「機器跟系統」。

# 1.5 詞彙速查

名稱一句話定義
雲端運算透過網路按需取得 IT 資源，依使用量付費
IaaS提供基礎設施，作業系統以上自己管 (EC2)
PaaS提供平台，只管程式碼與資料 (Elastic Beanstalk)
SaaS直接提供完整軟體服務 (Gmail、WorkSpaces)
混合部署雲端資源與自建機房互相連接運作
AWS CAF雲端採用框架，六個觀點指引上雲規劃

# 重點回顧

  • 雲端運算 = 按需取得 + 依使用量付費，不必自建與維護實體設備。
  • 三種服務模型：IaaS (自己管作業系統)、PaaS (只管程式碼)、SaaS (直接用)。
  • 三種部署模型：全雲端、混合、自建 (私有雲)。
  • 六大優勢：資本支出變營運支出、規模經濟、不必猜容量、速度與敏捷、不必養資料中心、分鐘級全球部署。
  • AWS CAF 六觀點：業務、人員、治理 (業務面)+ 平台、安全、營運 (技術面)。

# 自我測驗

EC2 屬於哪一種服務模型?Elastic Beanstalk 呢?

答：EC2 是 IaaS,Elastic Beanstalk 是 PaaS。 判斷關鍵是「你要不要管作業系統」——EC2 要，Beanstalk 不用。

「不必再猜測容量」屬於雲端運算六大優勢中的哪一項?為什麼重要?

答：第 3 項。 傳統採購必須事先賭需求量，買太多浪費、買太少當機；雲端可以隨需求即時增減，消除這個賭注。

AWS CAF 的六個觀點中,哪三個屬於「業務能力」?

答：業務 (Business)、人員 (People)、治理 (Governance)。 另外三個平台、安全、營運屬於技術能力。

公司把部分系統留在自己機房,部分搬上 AWS 並互相連通,這是哪種部署模型?

答：混合部署 (Hybrid)。 雲端資源與自建基礎設施整合運作。
